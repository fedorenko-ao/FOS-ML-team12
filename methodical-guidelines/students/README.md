# Методические указания для студентов

Данный репозиторий содержит общие правила, структуру и требования к выполнению самостоятельных работ (СР) и итогового мини-проекта по курсу.

---

## 1. Общие требования

Все учебные практикумы, самостоятельные работы и итоговый мини-проект выполняются в формате **Jupyter Notebook** или **Google Colab**.

**Студент обязан:**
- использовать **индивидуальный вариант**;
- выполнять работу **самостоятельно**;
- соблюдать структуру шаблона;
- обеспечивать **воспроизводимость** результатов;
- давать пояснения к коду и полученным результатам;
- соблюдать **академическую добросовестность**.

---

## 2. Настройка окружения

### Работа в Google Colab
1. Откройте notebook по предоставленной ссылке.
2. Создайте собственную копию.
3. Загрузите датасет или подключите Google Drive.
4. При необходимости установите дополнительные библиотеки.
5. Выполняйте ячейки последовательно (сверху вниз).
6. Перед отправкой выполните:  
   `Runtime → Restart session and run all`

### Локальный запуск
Рекомендуется использовать **Python 3.10** или более новую совместимую версию.

## 4. Структура сдаваемых материалов


### Для итогового мини-проекта
```text

```

**Важно:** имена файлов должны быть понятными и не содержать случайных обозначений.

---

## 5. Требования к Notebook

Notebook должен:
- выполняться сверху вниз без ошибок;
- использовать относительные пути;
- содержать постановку задачи;
- включать описание данных;
- демонстрировать preprocessing;
- содержать обучение и сравнение моделей;
- включать метрики и графики;
- содержать анализ ошибок;
- завершаться выводами и ограничениями.

**Запрещается** вручную изменять результаты выполнения ячеек.

---

## 6. Проверка перед отправкой

Перед сдачей обязательно выполните:
- [ ] `Restart Kernel and Run All`
- [ ] проверку отсутствия ошибок
- [ ] проверку относительных путей
- [ ] проверку отображения всех графиков и таблиц
- [ ] проверку соответствия индивидуальному варианту
- [ ] проверку наличия выводов
- [ ] проверку отсутствия data leakage
- [ ] проверку списка использованных источников
- [ ] проверку имени файла и структуры папки

**Исходные датасеты не должны изменяться вручную.**

---

## 7. Использование LLM и внешнего кода

**Разрешается** использовать LLM для:
- объяснения теории;
- поиска ошибок;
- обсуждения вариантов решения;
- генерации небольших вспомогательных фрагментов.

**Студент обязан:**
- понимать весь представленный код;
- проверять корректность результата;
- уметь объяснить основные шаги;
- указывать внешние источники;
- кратко отметить использование LLM в конце notebook.

**Запрещается:**
- сдавать полностью сгенерированную работу без проверки;
- использовать чужой notebook без указания источника;
- передавать свой индивидуальный вариант другим студентам;
- представлять чужой код как собственный.

---

## 8. Академическая добросовестность

Все работы выполняются **индивидуально**. При обнаружении одинакового кода, выводов или несоответствия решений варианту преподаватель может провести дополнительную устную проверку.

Студент должен уметь:
- объяснить preprocessing;
- обосновать выбор модели;
- объяснить выбранные метрики;
- показать, где формируется train/test split;
- объяснить любой фрагмент представленного кода.

---

## 9. Сроки сдачи

Актуальные сроки публикуются преподавателем в **Moodle**, календаре дисциплины или другом официальном канале.  
Студент обязан **самостоятельно** контролировать срок сдачи. Работы, отправленные после установленного срока, проверяются в соответствии с правилами дисциплины.

## 10. Защита мини-проекта

На защите студент должен:
- кратко представить задачу и данные;
- объяснить preprocessing;
- обосновать выбор моделей;
- показать результаты на тестовой выборке;

- ответить на вопросы по notebook и коду.

**Презентация** должна содержать **6–8 слайдов**.  
Защита проводится **индивидуально**.
