# Методические указания для преподавателей
## Организация и проверка учебных работ

Данный документ содержит рекомендации по подготовке, проведению и оцениванию самостоятельных работ (СР) и итогового мини-проекта по дисциплине.

---

## 1. Подготовка учебных практикумов

Перед проведением практикума преподаватель обязан проверить:

- [ ] доступность notebook и датасета;
- [ ] корректность относительных путей;
- [ ] выполнение всех демонстрационных ячеек через `Restart Kernel and Run All`;
- [ ] отсутствие ошибок выполнения;
- [ ] наличие фиксированного `random_state` для стохастических методов;
- [ ] отсутствие использования test-данных при обучении preprocessing и подборе параметров;
- [ ] корректное отображение таблиц и графиков;
- [ ] наличие двух мини-заданий для студентов;
- [ ] соответствие практикума заявленному индикатору и результату обучения.

**Важно:** ячейки с мини-заданиями должны оставаться пустыми и невыполненными.

---

## 2. Подготовка и распределение индивидуальных вариантов

Для СР №1–3 и итогового мини-проекта используются банки индивидуальных вариантов.

### Процедура назначения вариантов:
1. Каждому студенту назначается индивидуальный вариант.
2. Распределение фиксируется в таблице.
3. Проверяется уникальность варианта в группе.
4. Студенту передаются соответствующие датасеты и шаблон notebook.
5. При пересдаче назначается **новый вариант** сопоставимой сложности.

> **Недопустимо** повторное использование студентом того же варианта при пересдаче.

## 4. Проверка notebook

При проверке оценивается **корректность всего ML-процесса**, а не только итоговые метрики.

### Контрольный список проверки:
- [ ] воспроизводимость выполнения (Restart & Run All);
- [ ] отсутствие data leakage;
- [ ] корректность train/validation/test-разделения;
- [ ] применение preprocessing только на обучающих данных;
- [ ] обоснование выбора модели и метрик;
- [ ] корректность cross-validation;
- [ ] анализ ошибок и ограничений модели;
- [ ] соответствие решения индивидуальному варианту;
- [ ] самостоятельность выводов;
- [ ] способность студента объяснить использованный код.

При сомнении в самостоятельности выполнения проводится **краткая устная проверка**.

## 5. Версионирование ресурсов

Для материалов дисциплины используется семантическое версионирование:

- `v1.0` — первая утверждённая версия;
- `v1.1` — небольшие исправления и дополнения;
- `v2.0` — существенное изменение содержания или структуры.

### Информация об обновлении:
- номер версии;
- дата изменения;
- краткое описание изменения;
- автор изменения.

Старые версии **не удаляются** до завершения текущего семестра.

## 6. Работа с внешними ссылками

Часть материалов может размещаться во внешнем хранилище.

### Перед началом каждого модуля проверьте:
- [ ] доступность основной ссылки;
- [ ] корректность прав доступа;
- [ ] наличие резервной копии;
- [ ] соответствие версии ресурса заданию;
- [ ] отсутствие изменений в структуре датасета.

При недоступности внешнего сервиса используйте резервную копию или локальную версию.

---

## 7. Использование LLM и внешнего кода

**Разрешается** использовать генеративный ИИ для:
- объяснения теоретических понятий;
- поиска и исправления ошибок;
- обсуждения вариантов реализации;
- генерации отдельных вспомогательных фрагментов кода.

**Студент обязан:**
- понимать весь представленный код;
- проверить корректность результата;
- уметь объяснить основные решения;
- указать использование LLM или внешнего источника;
- **не выдавать** полностью сгенерированное решение за самостоятельное.

> Код, который студент не может объяснить, **не засчитывается**.

## 8. Обратная связь

Обратная связь предоставляется через:
- комментарии в notebook;
- Moodle или другую образовательную систему;
- устно во время занятия или консультации.

### Комментарий преподавателя должен содержать:
- выполненные требования;
- обнаруженные ошибки;
- недостающие элементы;
- рекомендации по исправлению;
- итоговый балл по рубрике.

---

## 9. Апелляция

Студент может запросить пересмотр оценки при несогласии с применением рубрики.

### Порядок апелляции:
1. Студент указывает конкретный критерий рубрики.
2. Прикладывает ссылку на соответствующий фрагмент работы.
3. Преподаватель повторно проверяет **только оспариваемый критерий**.
4. Решение оформляется кратким комментарием.

Повторная проверка проводится по **той же рубрике**, что и при первоначальном оценивании.
