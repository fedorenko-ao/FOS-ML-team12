# ЛР 16. Мониторинг данных и выявление drift

## Цель

Научиться сравнивать reference- и current-данные и определять, какие изменения действительно могут влиять на работу ML-модели.

## Постановка

Студент получает `reference.csv`, `current.csv`, описание признаков и краткий паспорт модели. Target в текущем периоде может быть недоступен.

## Обязательная последовательность

1. Проверить схему данных: столбцы, типы, диапазоны, missingness, новые/исчезнувшие категории.
2. Для числовых признаков сравнить распределения, квантили и минимум один количественный критерий.
3. Для категориальных признаков сравнить доли, новые и редкие категории.
4. Выделить признаки с наиболее сильным изменением.
5. Сформулировать минимум **три гипотезы** причины: сезонность, новый сегмент, смена источника, единицы измерения, изменение процесса сбора и т. п.
6. Для каждой гипотезы указать проверку, которая способна её подтвердить или ослабить.
7. Сделать инженерный вывод: изменений нет / drift допустим / нужен мониторинг / нужен пересмотр / данных недостаточно.

## Мини-задание 1

Найти минимум два признака, по которым reference и current существенно различаются, и доказать различие визуально и количественно.

## Мини-задание 2

Заполнить таблицу минимум из 4 строк:

| Факт | Возможная причина | Альтернативное объяснение | Как проверить |
|---|---|---|---|

## Недостаточные выводы

- «p-value < 0.05, значит модель сломалась»;
- «распределение стало другим, надо переобучать»;
- «графики похожи, значит всё нормально».

Drift данных — сигнал для анализа, а не автоматический диагноз модели.

## Текущий контроль

| Балл | Критерий |
|---:|---|
| 2 | Анализ воспроизводим; изменения доказаны; факт отделён от интерпретации; гипотезы проверяемы |
| 1 | Анализ частичный или выводы недостаточно обоснованы |
| 0 | Результат не воспроизводится либо drift объявляется без анализа |
